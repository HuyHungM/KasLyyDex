# Netlify deployment — Task 2 local integration status

## No cloud work in this task

No Netlify login, site creation, site link, environment-variable write, deploy,
domain change or rollback was performed here. Cloud work remains an owner-gated
operation. This document records the commands an operator runs and the checks
that stay manual; it does not claim any site or Deploy Preview exists.

## Build configuration

Root `netlify.toml` sets `base = "web"`, `command = "npm run build"` and
`NODE_VERSION = "22"`. It deliberately leaves `publish` unset and does not pin
a Next.js adapter: the platform's zero-config Next.js support selects it.
`npm run build` still requires the WASM glue generated by `npm run build:wasm`
before it is run locally; see `README.md`.

## Environment variables

The tracked template `web/.env.example` lists names only:

```
NETLIFY_DB_URL=
RUST_CONTENT_API_ORIGIN=
READER_TICKET_SECRET=
```

Real values belong in Netlify site environment settings (UI or CLI) and in the
gitignored local `.env.local`; never commit them. From the repository root an
operator can:

```bash
netlify login
netlify link
netlify env:list
netlify env:set NETLIFY_DB_URL '<owner-supplied connection string>'
netlify env:set RUST_CONTENT_API_ORIGIN '<owner-supplied service URL>'
netlify env:set READER_TICKET_SECRET '<owner-supplied secret>'
```

`READER_TICKET_SECRET` must be at least 32 characters; missing or short values
make the progression routes fail closed with 503. `RUST_CONTENT_API_ORIGIN` is
the public URL of the Axum content service (see `infra/axum.md`; deployment
target is documented in `infra/northflank.md`), not a Netlify-hosted service.

## Preview and production verification

```bash
npm ci
npm run build:wasm
npm run build:web
npm run test:aggregate
netlify dev
```

Run a local Axum binary alongside `netlify dev` so the same-origin
`/api/content/*` boundary has a real upstream. A Deploy Preview, when the owner
creates one, must be verified against a dedicated database branch before any
production publish. No preview URL is asserted here.

## Rollback

- Frontend: use Netlify deploy history to publish a previous successful deploy.
- Database: Netlify does not automatically revert schema changes. Coordinate
  migrations and take a backup before publishing a deploy that changes them.
- Auth/session changes: keep the previous published deploy until session,
  sign-in and callback checks pass on the candidate deploy.

## Axum limitation

Netlify is not a host for the long-lived Axum content service: there is no Rust
buildpack or always-on process in this setup. The Next.js site talks to Axum
only through `RUST_CONTENT_API_ORIGIN`, pointed at the separate service. Do not
try to fold `cargo build -p server` into the Netlify build command.
