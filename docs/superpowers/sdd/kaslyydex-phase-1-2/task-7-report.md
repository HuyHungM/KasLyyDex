## What was implemented

### Schema and migrations

`web/lib/db/schema.ts` + `web/drizzle/0002_comments_moderation.sql` (generated by Drizzle Kit, journal/snapshot updated) add application-owned tables only:

- `comment_threads(target_type, target_id, locked, locked_by, updated_at)` — lock state is a thread row, not a comment status.
- `comments` with opaque `user_id` FK, `spoiler`, `body`, one-level `parent_id`, timestamps, statuses constrained to `visible|hidden|removed`, and checks for target type/self-parent.
- `comment_reports` with a partial unique index `(user_id, comment_id) WHERE status='open'`, resolved/dismissed state and cascade cleanup.
- `notifications` with a unique `(user_id, event_key)` index — the shared dedup contract for Task 8 level-up events.
- `notification_cursors(user_id, manga_id, language, last_publish)` for per-language chapter comparison state.
- `action_events(user_id, action, occurred_at)` with an index, serving durable sliding-window counters.

Every user-owned new table cascades when the profile is deleted. No `neon_auth` schema/table is touched.

### HTTP surface

| Route | Methods | Notes |
|---|---|---|
| `/api/v1/comments` | GET, POST | Public paginated reads; authenticated create with 1–2000 trimmed plain-text body, spoiler flag and root-only `parentId`. |
| `/api/v1/comments/[id]` | PATCH, DELETE | Owner-only edit and soft removal (body nulled on removal). |
| `/api/v1/reports` | POST | Auth, reason 1–300 chars, no self-report, one open report per user/comment. |
| `/api/v1/moderation/reports` | GET | Open-report queue with moderator-only comment bodies. 403 for readers/anonymous. |
| `/api/v1/moderation/reports/[id]` | PATCH | Resolve/dismiss an open report. |
| `/api/v1/moderation/comments/[id]` | PATCH | Hide/remove/restore with notification to the author. |
| `/api/v1/moderation/threads` | GET, PUT | Read/toggle thread lock. PUT is moderator-only. |
| `/api/v1/moderation/access` | GET | Session-specific capability probe for the UI; `connection()`-guarded. |
| `/api/v1/notifications` | GET | Paginated inbox plus total unread count. |
| `/api/v1/notifications/refresh` | POST | On-demand bounded followed-chapter check. |
| `/api/v1/notifications/read` | POST | Owned-only mark-read for 1–100 ids. |

All responses use `private, no-store`, `Vary: Cookie` and `nosniff`; every mutation calls the existing `requireOrigin()` guard. Role/title/level/user-id fields in request bodies are rejected by strict allowlists; identity comes only from the managed session, and roles only from `user_roles` (bootstrapped by the verified-email allowlist in `ensureProfile`).

### Services, abuse limits and privacy

- `web/lib/moderation.ts` holds comments, reports, moderation, notifications and the reusable `emitNotification(db, {userId, type, eventKey, title, body, href})` interface used by reply, moderation and new-chapter events; Task 8 can pass a `level:<n>` event key through the same function.
- **Durable rate limits:** `pg_advisory_xact_lock(hashtext('community-rate:' + action + ':' + userId))` serialises one user/action inside the transaction, inserts an `action_events` row, counts events in the last 60 min/60 s and rolls the whole transaction back on violation. Limits: 5 comments/minute, 10 reports/hour. No module-local counter exists.
- **Reply rules:** parent must be a visible root in the same `(target_type, target_id)`; cross-thread, deep, removed/hidden-parent and locked-thread replies are rejected. `ensureThread()` takes `SELECT … FOR UPDATE` on the thread row, so lock changes and comment creation serialize.
- **Privacy:** `commentDto()` nulls `body` unless status is `visible`; hidden/removed roots are absent for non-owners; replies under a moderated root are not returned. The moderator queue is the only route that can read a hidden body. Counts never include moderated content.
- Pagination is cursor-based with `limit` capped at 50 (default 20); notification mark-read is capped at 100 ids; JSON bodies are capped by the existing 24 KiB reader.
- Moderator permission is checked in the routed handler (`withUser({ moderator: true })`) **and** again inside each service action via `requireModerator()`.

### Notifications

- Reply events (`reply:<commentId>`), moderation events (`moderation:<commentId>:<action>`) and new-chapter events (`chapter:<userId>:<manga>:<chapter>:<language>`) all go through `emitNotification()` with unique event keys. Per-comment spoiler text is replaced by a hint in the reply notification.
- `refreshFollowedChapters()` runs only when an authenticated user opens the library or notification center. It scans at most 20 followed (non-dropped) manga via the existing Axum `ContentClient`, accepts at most 3 new chapters per manga/language, persists a per-language publish cursor, and uses `pg_try_advisory_xact_lock` plus event-key uniqueness to make overlapping refreshes idempotent. The first observation stores a baseline from currently published chapters; no historic archive batch is emitted. No scheduler or worker was added.

### UI

- `components/comments/CommentSection.tsx` is mounted on manga detail and reader pages. Bodies render as React text (`{body}` with `whitespace-pre-wrap`), never `dangerouslySetInnerHTML`; spoiler bodies are absent from the DOM until revealed. Signed-in users can compose, reply, edit/delete their own comments and open a report dialog with reason + API error display.
- `components/notifications/NotificationCenter.tsx` provides the header bell/unread badge, compact panel and `/thong-bao` page with mark-read actions and a moderator link when the access probe succeeds.
- `components/moderation/ModerationQueue.tsx` on `/kiem-duyet` calls the real hide/remove/restore, resolve/dismiss and thread-lock APIs and displays structured API errors.
- `useRemoteResource()` is used with `session.user.id` as the identity key in comments, notifications, moderation and the synced library, so account switches cannot paint another account's ownership/queue state. Library and notification mounts trigger the bounded refresh.

### Implemented changes

1. **Composite chapter cursor — no permanent loss.** `0003_community_cursor_scrub.sql` adds `notification_cursors.last_chapter_id text NOT NULL DEFAULT ''`. The refresh orders candidates by `(publish_at, chapter_id)` and emits only candidates lexicographically after `(last_publish, last_chapter_id)`, capped at 3 per manga/language per refresh. The cursor advances **only through the last candidate actually processed**, so 7 same-timestamp chapters arrive as 3/3/1/0 across four refreshes and a later id at the same timestamp is still new. Baseline creation still stores the newest observed key and emits nothing; empty or failed upstream responses leave the cursor untouched. Legacy rows keep `''`, so equal-timestamp chapters are re-evaluated once but `(user,event_key)` uniqueness prevents duplicates. The external fetch remains inside the bounded transaction (≤20 content calls): this keeps cursor writes atomic with emitted notifications, at the tradeoff of holding a DB connection during those bounded fetches; moving the fetch out would need a two-phase reconciliation we did not invent.
2. **Reply notifications carry no body.** `createComment()` now emits a constant neutral hint for every reply (spoiler or not), so moderation cannot uncover a stored snippet. The new migration scrubs previously persisted `comment_reply` rows whose `event_key LIKE 'reply:%'`; a test seeds a legacy row under migrations 0000–0002, applies 0003 and proves the old secret is gone. Spoiler conceal/reveal in the public UI is unchanged and re-verified in the browser.
3. **Refresh scope.** The globally mounted header `NotificationCenter` no longer auto-refreshes; it only reads the inbox for the badge. `/thong-bao` mounts with `autoRefresh`, `/tu-truyen` keeps its single library-entry refresh, and the compact bell calls refresh only when explicitly opened on another page (once per opening, suppressed on library/notification pages). Browser test counts 0 refresh POSTs on home/search/account, 1 on library, 1 on notification entry, 1 on explicit header-panel opening.
4. **Moderator queue body.** `listReports()` now builds a privilege-specific DTO: a hidden comment's body is exposed only after the handler's moderator check and the service's `requireModerator()`; removed bodies stay null because removal destroys them. Ordinary public/owner comment reads still return `body: null` for moderated statuses, and queue GETs return 403 for anonymous and non-moderator readers. The original report's claim that the queue could show hidden bodies is now backed by a direct test rather than code inspection.
5. **Restore guard.** `moderateComment()` rejects `restore` unless the stored status is `hidden` and the body is intact (`409 RESTORE_NOT_ALLOWED`). Owner-deleted and moderator-removed comments cannot be resurrected; hidden→visible still works. The queue shows *Khôi phục* only for hidden comments. A SQL assertion proves there are no `visible` rows with a null body.

Reviewer minors (reply reply-cap 500, self/duplicate-report quota interaction, transaction spanning HTTP, stray test argument) were deliberately left for final review; no broad refactor was attempted. A new nearby test proves public comment GET tolerates an unconfigured auth service: the injected handler returns 200 for a guest, and the built route with no auth/DB env fails at `DATABASE_NOT_CONFIGURED` (not `AUTH_NOT_CONFIGURED`) with `private, no-store`.
